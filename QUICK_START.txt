# Qrate Quick Start Guide

## What is Qrate?

Qrate is a high-performance CSV editor that uses SQLite as its storage format (.qrate files).
Unlike traditional CSV editors, Qrate can handle massive datasets (1GB+) with instant load times
and crash-resistant reliability through ACID transactions.

## Getting Started

### 1. Install Dependencies

```bash
pnpm install
```

### 2. Run Development Server

```bash
pnpm run tauri dev
```

This will:
- Compile the Rust backend
- Start the Vite dev server
- Launch the Tauri application window

### 3. Using the Application

#### Opening Files

Three ways to get started:

1. **Import CSV** - Convert an existing CSV file to .qrate format
   - Click "Import CSV" in the sidebar
   - Select your CSV file
   - Choose where to save the .qrate file
   - Data is imported and the file opens automatically

2. **Open .qrate File** - Open an existing .qrate database
   - Click "Open .qrate File"
   - Select a previously created .qrate file

3. **Create New File** - Start with a blank .qrate file
   - Click "New .qrate File"
   - Choose where to save it
   - Add columns and data manually

#### Working with Data

**Editing Cells:**
- Double-click any cell to edit
- Changes save automatically to the database
- No manual "Save" needed

**Column Operations:**
- Drag column borders to resize (width persists)
- Click column headers to sort
- Use filters (if implemented)

**Navigation:**
- Scroll vertically to browse data
- Only visible rows are loaded (virtual scrolling)
- Smooth performance even with millions of rows

## .qrate File Format

A .qrate file is a SQLite database with three tables:

### _meta (Workspace Settings)
```sql
CREATE TABLE _meta (
    key TEXT PRIMARY KEY,    -- Setting name
    value TEXT NOT NULL      -- Setting value (JSON or string)
);
```

Examples:
- `version`: "1.0"
- `created_at`: "2024-01-15 10:30:00"
- `viewport_scroll_y`: "1000"

### _columns (Column Definitions)
```sql
CREATE TABLE _columns (
    id TEXT PRIMARY KEY,     -- Column ID (e.g., "col_0")
    name TEXT NOT NULL,      -- Display name
    type TEXT NOT NULL,      -- Data type (Text, Number, Date)
    width INTEGER NOT NULL,  -- Width in pixels
    hidden INTEGER NOT NULL  -- Visibility flag (0/1)
);
```

### data (Content)
```sql
CREATE TABLE data (
    row_id INTEGER PRIMARY KEY AUTOINCREMENT,
    [col_0] TEXT,  -- Dynamic columns added via ALTER TABLE
    [col_1] TEXT,
    ...
);
```

## Common Tasks

### Add a New Tauri Command

1. Define the command in `src-tauri/src/lib.rs`:
```rust
#[tauri::command]
fn my_command(state: State<AppState>, param: String) -> Result<String, String> {
    // Implementation
    Ok("Success".to_string())
}
```

2. Register it in the `invoke_handler`:
```rust
.invoke_handler(tauri::generate_handler![
    // ... existing commands
    my_command
])
```

3. Call from frontend:
```typescript
import { invoke } from '@tauri-apps/api/core';

const result = await invoke<string>('my_command', { param: 'value' });
```

### Add a New Database Operation

1. Add function to `src-tauri/src/database.rs`:
```rust
pub fn my_operation(conn: &Connection, param: &str) -> Result<()> {
    conn.execute("SQL QUERY HERE", params![param])?;
    Ok(())
}
```

2. Call from a Tauri command:
```rust
#[tauri::command]
fn my_command(state: State<AppState>, path: String, param: String) -> Result<(), String> {
    let conn_arc = state.get_connection(&path)
        .ok_or_else(|| "File not open".to_string())?;
    let conn = conn_arc.lock().unwrap();

    database::my_operation(&conn, &param)
        .map_err(|e| format!("Error: {}", e))?;

    Ok(())
}
```

### Update the Store

Add methods to `qrateStore.svelte.ts`:
```typescript
async myMethod(param: string): Promise<void> {
    if (!this.currentFilePath) {
        throw new Error('No file is currently open');
    }

    try {
        await invoke('my_command', {
            path: this.currentFilePath,
            param,
        });

        // Update local state if needed

    } catch (err) {
        this.error = err instanceof Error ? err.message : String(err);
        throw err;
    }
}
```

## Performance Tips

1. **Large CSV Imports**: Use the import_csv_to_qrate command instead of loading into memory
2. **Batch Operations**: Wrap multiple inserts/updates in a transaction
3. **Virtual Scrolling**: Keep currentLimit around 100 rows for optimal performance
4. **Column Operations**: Soft-delete columns (set hidden=1) instead of ALTER TABLE DROP

## Troubleshooting

### "Failed to open database"
- Check file path is absolute
- Ensure file has .qrate extension
- Verify file permissions

### "No file is currently open"
- File must be opened before operations
- Check `qrateStore.isFileOpen` state

### Grid not rendering
- Ensure SSR is disabled (`+page.ts` with `export const ssr = false`)
- Check browser console for errors
- Verify RevoGrid dependencies are installed

### Slow performance
- Reduce currentLimit in store (default: 100)
- Check SQL query complexity
- Use indexes on frequently queried columns
