================================================================================
                          DATA FLOW: OPENING A FILE
================================================================================

USER ACTION: Click "Open .qrate File" → Select "data.qrate" (1GB, 1M rows)

Step 1: Frontend
┌────────────────────────┐
│  FileManager.svelte    │
│  handleOpenQrate()     │──→ User clicks "Open .qrate File"
└────────────────────────┘
            │
            ├──→ Tauri Dialog: Select file
            │
            ▼
┌────────────────────────┐
│  qrateStore            │
│  openFile(path)        │──→ invoke('open_qrate_file', { path })
└────────────────────────┘
            │
            │ IPC Call with path string (~100 bytes)
            ▼
═══════════════════════════════════════════════════════════════════
                        NETWORK BOUNDARY
═══════════════════════════════════════════════════════════════════
            │
            ▼
Step 2: Backend
┌────────────────────────┐
│  Tauri Command         │
│  open_qrate_file()     │──→ Receives path
└────────────────────────┘
            │
            ├──→ database::open_database(&path)
            │       └─→ rusqlite::Connection::open()
            │              └─→ SQLite opens file handle
            │                     Time: ~10ms (just file I/O)
            │
            ├──→ database::get_columns()
            │       └─→ SELECT * FROM _columns
            │              Result: 4 columns × 50 bytes = 200 bytes
            │
            ├──→ database::get_row_count()
            │       └─→ SELECT COUNT(*) FROM data
            │              Result: Single number (1000000)
            │              Time: ~50ms (uses index, very fast)
            │
            ├──→ state.add_connection(path, conn)
            │       └─→ Store in DashMap for future queries
            │
            └──→ Return FileOpenResponse {
                    path: "C:/data.qrate",
                    columns: [...],      // ~200 bytes
                    total_rows: 1000000  // 8 bytes
                 }
            │
            │ IPC Response (~1 KB total)
            ▼
═══════════════════════════════════════════════════════════════════
                        NETWORK BOUNDARY
═══════════════════════════════════════════════════════════════════
            │
            ▼
Step 3: Frontend Update
┌────────────────────────┐
│  qrateStore            │
│  • currentFilePath     │──→ "C:/data.qrate"
│  • columns             │──→ [4 ColumnDef objects]
│  • totalRows           │──→ 1000000
│  • isFileOpen          │──→ true
└────────────────────────┘
            │
            ├──→ loadRows(0, 100)  // Load initial viewport
            │
            ▼
┌────────────────────────┐
│  invoke('get_rows')    │──→ { path, offset: 0, limit: 100 }
└────────────────────────┘
            │
            ▼
═══════════════════════════════════════════════════════════════════
            │
            ▼
Step 4: Backend Query
┌────────────────────────┐
│  get_rows()            │
│  SELECT * FROM data    │
│  LIMIT 100 OFFSET 0    │──→ Query takes ~5ms (indexed)
└────────────────────────┘
            │
            └──→ Return 100 rows (~10 KB JSON)
            │
            ▼
═══════════════════════════════════════════════════════════════════
            │
            ▼
Step 5: Render
┌────────────────────────┐
│  RevoGrid.svelte       │
│  • rows = [100 rows]   │──→ Render viewport
│  • Display time: ~50ms │
└────────────────────────┘

TOTAL TIME: ~115ms for 1GB file!
MEMORY USED: ~100 MB (just viewport data)

================================================================================
                      DATA FLOW: IMPORTING CSV FILE
================================================================================

USER ACTION: Import "large.csv" (500MB, 1M rows) → Save as "imported.qrate"

Step 1: Frontend
┌────────────────────────┐
│  FileManager           │
│  handleImportCsv()     │──→ Select CSV file
│                        │──→ Select save location
└────────────────────────┘
            │
            ▼
┌────────────────────────┐
│  qrateStore            │
│  importCsv()           │──→ invoke('import_csv_to_qrate', {
│                        │        csvPath: 'C:/large.csv',
│                        │        qratePath: 'C:/imported.qrate'
│                        │    })
└────────────────────────┘
            │
            ▼
═══════════════════════════════════════════════════════════════════
            │
            ▼
Step 2: Backend Processing
┌────────────────────────────────────────────────────────────────┐
│  import_csv_to_qrate()                                         │
│                                                                │
│  1. csv::Reader::from_path(csvPath)                           │
│     └─→ Read headers: ["Name", "Email", "Age", ...]          │
│            Time: ~10ms                                         │
│                                                                │
│  2. Create/Open .qrate database                                │
│     └─→ init_database() or open_database()                    │
│            Time: ~20ms                                         │
│                                                                │
│  3. BEGIN TRANSACTION  ◄── Critical for performance!          │
│                                                                │
│  4. For each header:                                           │
│     └─→ add_column(ColumnDef { id: "col_0", name: "Name" })  │
│            └─→ INSERT INTO _columns                            │
│            └─→ ALTER TABLE data ADD COLUMN [col_0] TEXT       │
│            Time: ~5ms per column × 10 columns = 50ms           │
│                                                                │
│  5. Prepare INSERT statement:                                  │
│     "INSERT INTO data (col_0, col_1, ...) VALUES (?, ?, ...)" │
│                                                                │
│  6. For each CSV row (1 million rows):                         │
│     └─→ stmt.execute(row_values)                              │
│            └─→ Batched in transaction (very fast)             │
│            Time: ~5 seconds for 1M rows                        │
│                                                                │
│  7. COMMIT TRANSACTION  ◄── Single disk sync                  │
│            Time: ~500ms                                        │
│                                                                │
│  8. get_columns() → get_row_count()                            │
│            Time: ~50ms                                         │
│                                                                │
│  9. Return FileOpenResponse                                    │
└────────────────────────────────────────────────────────────────┘
            │
            ▼
═══════════════════════════════════════════════════════════════════
            │
            ▼
Step 3: Frontend Display
┌────────────────────────┐
│  qrateStore            │
│  • File now open       │──→ Load initial viewport
│  • Ready for editing   │
└────────────────────────┘

TOTAL TIME: ~6 seconds for 500MB CSV
MEMORY PEAK: ~100MB (streaming CSV read)
RESULT: Optimized .qrate file on disk, ready for instant future opens

================================================================================
                           CONCURRENCY MODEL
================================================================================

Multiple Files Open Simultaneously:

┌─────────────────────────────────────────────────────────────────┐
│                          AppState (DashMap)                     │
│                                                                 │
│  Thread-Safe Concurrent Hash Map                               │
│                                                                 │
│  ┌───────────────────┐   ┌───────────────────┐                │
│  │ "file1.qrate"     │   │ "file2.qrate"     │                │
│  │   ↓               │   │   ↓               │                │
│  │ Arc<Mutex<Conn>>  │   │ Arc<Mutex<Conn>>  │                │
│  └────────┬──────────┘   └────────┬──────────┘                │
│           │                       │                            │
│           │    No Conflicts       │                            │
│           ↓                       ↓                            │
│  ┌────────────────┐      ┌────────────────┐                   │
│  │  file1.qrate   │      │  file2.qrate   │                   │
│  │  file1.qrate   │      │  file2.qrate-wal                   │
│  │  -wal          │      │  file2.qrate-shm                   │
│  │  file1.qrate   │      │                │                   │
│  │  -shm          │      │                │                   │
│  └────────────────┘      └────────────────┘                   │
│                                                                │
│  Each file has independent:                                    │
│  • SQLite connection                                           │
│  • WAL file (write-ahead log)                                  │
│  • Shared memory region                                        │
│                                                                │
│  Multiple readers can access simultaneously (WAL mode)         │
└─────────────────────────────────────────────────────────────────┘
