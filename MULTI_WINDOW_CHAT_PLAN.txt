# Multi-Window Support + Chat Sidebar Layout — Implementation Plan
# Adapted for Svelte 5 + Tauri 2 Architecture

This plan adapts VS Code's multi-window and chat sidebar patterns for qRate's Svelte/Tauri stack.
Focus: Multi-window infrastructure and chat sidebar layout only (no chat logic/LLM integration).

===============================================================================
## ARCHITECTURAL PRINCIPLES
===============================================================================

1. RUST-HEAVY PHILOSOPHY
   - Window state management → Rust (SQLite or JSON file)
   - Layout persistence → Rust
   - IPC coordination → Rust (Tauri event system)
   - Cross-window sync → Rust state manager
   - File system operations → Rust

2. SVELTE-LIGHT PHILOSOPHY
   - UI rendering only
   - Local component state (collapsed/expanded, animations)
   - Reactivity to Rust state changes
   - User interactions → invoke Rust commands

3. TAURI INTEGRATION
   - Use Tauri's WebviewWindow API for OS windows
   - Use Tauri's event system for cross-window messaging
   - Use existing invoke pattern for Rust commands
   - Leverage Tauri's window state plugin for bounds/position

## LAYOUT MODEL (RUST-MANAGED)
===============================================================================

Rust Structure (src-tauri/src/layout/mod.rs):

pub struct WindowLayout {
    pub version: u32,
    pub window_id: String,
    pub workspace_path: Option<String>,

    pub left_sidebar: SidebarState,
    pub right_sidebar: SidebarState,
    pub bottom_panel: PanelState,
    pub chat_sidebar: ChatSidebarState,
    pub editor_area: EditorAreaState,

    pub window_bounds: WindowBounds,
}

pub struct SidebarState {
    pub visible: bool,
    pub width: u32,
    pub active_view_id: String,
}

pub struct ChatSidebarState {
    pub visible: bool,
    pub width: u32,
    pub mode: ChatMode, // Docked | Panel | Detached
    pub detached_window_id: Option<String>,
}

pub enum ChatMode {
    Docked,   // Right sidebar
    Panel,    // Bottom panel
    Detached, // Separate window
}

Persistence Strategy:
- Store in SQLite: workspace_layouts table
- One row per window, keyed by window_id
- Serialize to JSON for flexibility
- Atomic updates with transactions
- Auto-save on layout change (debounced in Rust)

4.3 Mode Transitions
    Logic in chatStore.svelte.ts:

    Docked → Panel:
    1. Save current docked state
    2. Update layoutStore (mode = Panel)
    3. Animate transition
    4. Rust persists change

    Docked → Detached:
    1. Save current state
    2. Call windowManager.createChatWindow()
    3. Update layoutStore (mode = Detached, detachedWindowId)
    4. Hide local chat component
    5. Rust creates window with chat-only layout

    Detached → Docked:
    1. Close detached window
    2. Update layoutStore (mode = Docked)
    3. Show local chat component
    4. Restore previous width

5.2 Svelte Event Listeners

    $effect(() => {
        const unlisten = await listen('layout:changed', (event) => {
            if (event.payload.windowId !== windowStore.currentWindowId) {
                // Another window's layout changed
                // Optionally update shared state
            }
        });
        return () => unlisten();
    });

## NOTES & DECISIONS
===============================================================================

1. Single chat instance per window initially
   - Simpler mental model
   - Can add multiple chat windows later

2. Layout state is per-window, not shared
   - Each window has independent layout
   - Shared: theme, settings, recent files

3. Rust owns canonical state
   - Svelte stores are views into Rust state
   - Always sync from Rust on conflict

4. Detached windows are full WebviewWindows
   - Not lightweight popups
   - Full Tauri features available
   - Can have their own sidebars if needed

5. Backwards compatibility
   - Old workspace files work without layout metadata
   - Default layout applied automatically
   - Graceful degradation
