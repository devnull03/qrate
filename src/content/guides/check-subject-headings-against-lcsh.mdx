A subject column is only as useful as it is consistent with the vocabulary it claims to use.
`World War 1`, `WWI` and `World War, 1914-1918` are all readable, but only the last is the Library
of Congress subject heading, and only the last will link up with every other catalogue that uses
LCSH.

Checking headings by hand means a browser tab on id.loc.gov and a lot of copying. qrate can check
the whole column for you, against LCSH, GeoNames or Wikidata, and offer the closest authorised form
as a fix.

## Pick the authority for a column

1. Choose **Data ▸ Column Settings…**.
2. Under **Checked against**, pick the authority for the column:
   - **LCSH** for topical subjects.
   - **GeoNames** for places.
   - **Wikidata** for people, organisations and anything else with a Wikidata item.
3. If the column holds several headings per cell, set its **Value separator**, such as `|`, so each
   heading is checked on its own.

Values are checked over the network, so findings appear as the answers come back, not as you type.

## Read the findings

Each heading the authority does not recognise becomes an error in the Problems panel, saying which
authority turned it down:

The messages are specific to the authority:

- LCSH: “World War 1” is not a Library of Congress subject heading
- GeoNames: “Halifx” is not a place GeoNames knows
- Wikidata: “Agnes Vardaa” does not match anything in Wikidata

## Accept a suggestion

Where the authority has a close match, qrate offers it. Right-click the cell, open **Problems**, and
choose **Use “World War, 1914-1918”**. It replaces the cell's value as one change you can undo.

For many cells with the same heading, look for the group in the Problems panel: repeated findings
are grouped with a count, and fixing them is quicker from there.

Not every rejection is a mistake. A local heading, a new term, or a name the authority does not
hold yet can be correct. Choose **Ignore this occurrence**, or **Ignore in column** to accept that
value everywhere in the column.

## Set up GeoNames

GeoNames needs a free account with its web services turned on. Create one at geonames.org, enable
**Free Web Services** in your account page, then enter the username under **Settings ▸ Columns ▸
Authority accounts**. If GeoNames rejects the account, qrate stops sending requests and shows one
warning instead of an error per row. Fix the account in the same place to try again.
